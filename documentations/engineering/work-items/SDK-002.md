## SDK-002 — Inventory the public CE extension surface and host profiles

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** research · **Priority:** P1 · **Milestone:** SDK-M0

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

The previous audit distinguishes classic ABI exports, managed hosting, Lua globals and borrowed CE objects. The official comparison is pinned to a historical source revision, not to a measured CE 7.7 binary.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Build a source-indexed capability catalog with explicit supported and unqualified profiles.

**Expected benefit:** Build a source-indexed capability catalog with explicit supported and unqualified profiles.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] List classic slots, nine callback families, managed bootstrap services, Lua globals/object properties and relevant examples.
- [ ] Record exact symbol/path/line or declaration, native width, indirection, result shape, affinity and ownership.
- [ ] Separate host bitness from target bitness; no unsupported profile inferred from an enum member.

### Acceptance criteria

- [ ] Every claimed supported symbol has a source and explicit profile.
- [ ] Conflicting C/Pascal declarations are flagged, not silently reconciled.
- [ ] Opaque slots and source-only capabilities remain unavailable until qualified.

### Required validation

- [ ] Catalog completeness checks against the pinned declarations.
- [ ] A controlled host-profile probe records executable/Lua/bridge identities.

### Scope exclusions

- No unrelated rewrite, automatic capability activation, package publication, or repository-protection changes.
- Keep integration mechanisms in SDK and application policy/workflows in Client.
