## SDK-004 — Qualify classic ABI layouts and conflicting signatures

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** validation · **Priority:** P1 · **Milestone:** SDK-M1

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

Prior audit evidence includes direct-function slots, pointer cells, variables, nil entries, and conflicts such as GetAddressFromPointer and disassembly-related declarations.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Turn the ABI catalog into compiled, profile-specific layout and signature evidence.

**Expected benefit:** Turn the ABI catalog into compiled, profile-specific layout and signature evidence.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] Classify each slot before exposing typed calls; document pointer-cell dereference versus direct invocation.
- [ ] Compile layout probes for the supported host architecture and compare sizeof/offset/alignment.
- [ ] Resolve bool widths, address widths, calling conventions, buffer capacities and nullable slots from the actual implementation/profile.

### Acceptance criteria

- [ ] No guessed x64 layout or C-header-only interpretation is promoted to supported API.
- [ ] Every corrected projection has a regression and migration note.
- [ ] Unresolved signatures remain opaque or unavailable.

### Required validation

- [ ] Native compiler probes versus managed offset/size tests.
- [ ] Boundary values, null slots, truncated export table and table-size validation.
