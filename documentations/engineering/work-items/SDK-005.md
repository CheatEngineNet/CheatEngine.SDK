## SDK-005 — Qualify activation admission, shutdown, and plugin coexistence

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** validation · **Priority:** P1 · **Milestone:** SDK-M1

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

SDK host state is static within an assembly instance and the prior review identifies a one-plugin-per-load-context assumption. Client DI scopes do not prove assembly isolation.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Specify and test host admission/draining and multi-plugin coexistence independently of Client composition.

**Expected benefit:** Specify and test host admission/draining and multi-plugin coexistence independently of Client composition.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] Record enable/disable/re-enable transitions, callback rooting and runtime generation.
- [ ] Test two simultaneous plugins and selected side-by-side SDK versions with actual assembly/load-context identities.
- [ ] Define incomplete shutdown without detaching while admitted code can still access native state.

### Acceptance criteria

- [ ] Disabling plugin A does not invalidate B in a supported profile.
- [ ] Stale callbacks fail before invoking disposed plugin code.
- [ ] Queued/nested calls have documented admission and exception semantics.

### Required validation

- [ ] Deterministic barriers for disable versus worker dispatch.
- [ ] Live two-plugin/two-version enable and cleanup fixtures.
- [ ] Failure injection during enable and callback neutralization.

### Scope exclusions

- No unrelated rewrite, automatic capability activation, package publication, or repository-protection changes.
- Keep integration mechanisms in SDK and application policy/workflows in Client.
