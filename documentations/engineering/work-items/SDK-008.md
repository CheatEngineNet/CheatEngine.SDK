## SDK-008 — Own built-in runtime, process, symbol, and table Lua contracts

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** feature · **Priority:** P1 · **Milestone:** SDK-M2

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

ClientLuaGlobals currently declares built-in CE names and signatures. Using the SDK generator does not make the Client the correct owner of those integration facts.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Expose thin SDK semantic operations and factual runtime observations for the Client to consume.

**Expected benefit:** Expose thin SDK semantic operations and factual runtime observations for the Client to consume.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] Map every existing Client declaration to one SDK owner and exact source record.
- [ ] Handle target ISA/bitness/ABI, optional arguments, result kinds and missing globals without guesses.
- [ ] Keep exact-name ambiguity policy, table-root authorization and user-facing workflow composition in Client.

### Acceptance criteria

- [ ] A reviewed correspondence table covers the eleven declarations.
- [ ] Each operation has structured result and lifetime/thread contracts.
- [ ] SDK has no dependency on Client interfaces, options or DI.
