## SDK-011 — Make resource ownership handoff and cleanup exception-safe

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** feature · **Priority:** P1 · **Milestone:** SDK-M2

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

Owned scan/allocation/patch primitives already exist. Native success can precede managed owner construction or tracking; single-use disposal alone does not prove correct-target release.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Qualify each resource transition from native creation through managed adoption and release.

**Expected benefit:** Qualify each resource transition from native creation through managed adoption and release.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] Preserve child-before-parent scan cleanup and borrowed-versus-owned distinctions.
- [ ] Prepare bookkeeping before effects where possible; retain rollback authority until ownership transfers.
- [ ] Expose completed, partial or unknown effects and abandonment diagnostics; avoid blind destructive retries.

### Acceptance criteria

- [ ] Injected failure after native success never silently loses the cleanup responsibility.
- [ ] Double release is harmless without calling another target.
- [ ] A borrowed GUI record does not acquire automatic destruction on wrapper disposal.

### Required validation

- [ ] Failure at factory creation, owner adoption, tracking and each cleanup stage.
- [ ] Target replacement during owner lifetime.

### Scope exclusions

- No unrelated rewrite, automatic capability activation, package publication, or repository-protection changes.
- Keep integration mechanisms in SDK and application policy/workflows in Client.
