## SDK-013 — Qualify target memory, pointer width, and bounded buffer contracts

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** validation · **Priority:** P1 · **Milestone:** SDK-M3

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

The Client already routes typed memory to SDK primitives. Target x86 versus host x64 and partial transfer semantics must remain low-level facts.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Provide tested primitive contracts suitable for scoped Client codecs and bounded pointer workflows.

**Expected benefit:** Provide tested primitive contracts suitable for scoped Client codecs and bounded pointer workflows.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] Cover target-sized pointers, overflow, byte counts, capacities, encoding and ownership of returned buffers.
- [ ] Use explicit primitive marshalling; do not assume arbitrary unmanaged CLR layout matches target layout.
- [ ] Investigate bulk primitives only with a real CE contract and measured boundary savings.

### Acceptance criteria

- [ ] 32-bit target pointer reads are independent of host IntPtr.Size.
- [ ] Failure preserves byte/effect detail and no buffer outlives its native scope.
- [ ] No independent Client memory transport is required.

### Required validation

- [ ] Boundary/overflow/zero-length/partial-read fixtures.
- [ ] Controlled x86 and x64 target patterns.

### Scope exclusions

- No unrelated rewrite, automatic capability activation, package publication, or repository-protection changes.
- Keep integration mechanisms in SDK and application policy/workflows in Client.
