## SDK-014 — Separate AOB absence, errors, and execution bounds

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** feature · **Priority:** P1 · **Milestone:** SDK-M3

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

SDK AOB TryScan collapses causes and Client post-filters already materialized native results. A no-match representation is not yet independently live-qualified in this bootstrap.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Return factual scan outcomes and explicitly describe native execution bounds versus result limits.

**Expected benefit:** Return factual scan outcomes and explicitly describe native execution bounds versus result limits.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [x] Qualify the host meaning of nil before treating it as successful absence: normal `AOBScan` raw `nil` remains
  `NoResult`; only a valid zero-count `StringList` is `NoMatches`.
- [x] Expose range/module/early-stop capabilities only when CE supplies a verified contract: this AOB surface exposes
  none, and documents no SDK cancellation or result-limit execution bound.
- [x] Retain one SDK owner for every valid result list. It remains caller-owned until copied materialization and exactly
  one dispose; an owner whose count cannot be validated is released before the failure outcome returns.

### Acceptance criteria

- [x] No-match is distinct from missing global, Lua error, raw `nil`, malformed result and unreadable list count.
- [x] A result limit is never advertised as a bound on CE scan work.
- [x] Exact uniqueness is not inferred from an arbitrary early-stop result; this surface offers no early-stop control.

### SDK-014 implementation record — 2026-09-21

`AobScanner.TryScanOutcome` is additive to `TryScan` and `TryScanDetailed`. It carries the protected Lua status only
for a protected failure and never copies transient Lua error text. CE's normal string-form `AOBScan` documentation
states that it returns a caller-freed `StringList`, but does not assign normal-call `nil` a no-match meaning; the
implementation therefore classifies absence exclusively after successful object decoding and a non-negative count
read. The fixture contract proves the managed mapping and ownership path only. It neither executes Cheat Engine nor
qualifies result shape, affinity, cancellation, range/module behavior, or performance on a live host.
