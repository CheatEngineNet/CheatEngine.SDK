## SDK-019 — Qualify timer and hotkey subscription ownership

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** research · **Priority:** P2 · **Milestone:** SDK-M5

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

Client timer/hotkey contracts remain unavailable. Host subscriptions require rooted callbacks, teardown and runtime-generation contracts.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Provide SDK-owned subscription primitives only for qualified host behavior.

**Expected benefit:** Provide SDK-owned subscription primitives only for qualified host behavior.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [x] Define the internal registration contract: a registrar publishes only with a complete unregister action; managed callback and unregister failures are contained; unregister is single-use. Timer/hotkey affinity remains unqualified and is not exposed.
- [x] Neutralize and drain internal host-subscription callbacks before plugin-managed `OnDisable` state can be destroyed; unregister in LIFO order while the old Lua state is reachable.
- [x] Keep application scheduling policy and stream delivery outside SDK; no timer or hotkey lease is public.

### Acceptance criteria

- [x] The internal owner captures attachment epoch plus state generation and rejects stale, reset, disabled and re-enabled callbacks.
- [x] Repeated teardown consumes one unregister action and never retries it, including after an unregister failure.
- [x] No timer/hotkey event payload surface exists, so no borrowed host pointer is exposed.

### Required validation

- [x] Registration failure, callback racing pre-disable admission closure, reset and re-enable fixtures.
- [ ] Live host timer/hotkey teardown profile.

### Scope exclusions

- No unrelated rewrite, automatic capability activation, package publication, or repository-protection changes.
- Keep integration mechanisms in SDK and application policy/workflows in Client.

**SDK-019 implementation decision (2026-09-21):** The historical timer slots are outside the managed V1 export record,
and hotkeys have only a Lua-object path with no observable registration/removal confirmation. Historical source also
suggests a lock/synchronize teardown-deadlock canary for hotkey self-disposal. The SDK therefore implements only the
internal `LuaHostSubscription` lifecycle owner and exposes neither a timer nor a hotkey lease. A future facade must add
an exact-host profile for registration outcomes, callback affinity, disable/re-enable and teardown before promotion.

**Managed validation (2026-09-21):** `py eng/Validate-CeSurfaceCatalog.py` passed; `CheatEngine.SDK.Lua.Tests` passed
208/208; `CheatEngine.SDK.Hosting.Tests` passed 93/93; the Debug solution build and the standalone `win-x64` NativeAOT
publication probe passed with zero build warnings. The NativeAOT publication is build compatibility only, not a CE host
profile. No live host timer/hotkey teardown profile was run.
