## SDK-021 — Expose typed record and symbol mutation ownership

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** feature · **Priority:** P1 · **Milestone:** SDK-M2

### Maintainer notes

Keep execution updates, actual commands/results, decisions, and refinements here. The bootstrap does not overwrite an existing issue body on rerun.

SDK-021 implements `AddressListMutations` as ID-addressed commands against the current list, not a durable live-record
owner. `MemoryRecordMutationOutcome` represents a completed command separately from a later consumer snapshot; a
protected error after `destroy` or `Parent` assignment begins is indeterminate and is not retried. Hierarchy validation
rejects self-parent, cycles, missing records and bounded traversal before mutation.

`SymbolRegistrationLease` is deliberately a same-SDK coordinator, not a claim of CE-exclusive ownership: CE returns no
registration token and unregisters only by name. A stale/superseded coordinator lease does not unregister a later
same-coordinator registration; external scripts, plugins and SDK copies remain unobservable. Attach epoch or state
generation changes make the lease inert rather than directing cleanup at a new runtime.

Fixture validation covers the command, error and stack cases. Package compilation and Native AOT publication consume the
new public types without touching raw CE handles. No live Cheat Engine host run is claimed. Client adapter migration is
the separately scoped `CheatEngine.Client` issue 31.
