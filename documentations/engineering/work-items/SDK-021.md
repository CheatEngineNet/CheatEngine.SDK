## SDK-021 — Expose typed record and symbol mutation ownership

**Owner:** `CheatEngineNet/CheatEngine.SDK` · **Kind:** feature · **Priority:** P1 · **Milestone:** SDK-M2

**Initial status:** Needs refinement. **Runtime validation:** Not executed by this bootstrap.

### Context and evidence

Client generic Parent/destroy access and symbol declarations encode low-level CE semantics. Borrowed GUI records must not become automatic owners.

**Evidence classification:** InheritedAuditBasis + Proposal; revalidate the pinned call path before implementation.

### Outcome and rationale

Supply typed SDK mutation primitives and explicit effect/result contracts.

**Expected benefit:** Supply typed SDK mutation primitives and explicit effect/result contracts.

### Architectural responsibility

SDK owns CE mappings, native safety, factual outcomes and low-level owners. Client owns application policy, typed workflows, composition, and developer experience.

### Technical requirements and task checklist

- [ ] Resolve record IDs and relationship validity under the current host lifetime.
- [ ] Separate delete/reparent command outcomes from later snapshot refresh.
- [ ] Record symbol registration ownership and avoid erasing another component replacement.

### Acceptance criteria

- [ ] Client built-in adapters no longer manipulate Parent/destroy with raw Lua operations.
- [ ] Borrowed wrapper Dispose does not delete GUI-owned data.
- [ ] Mutation completed plus refresh failed is representable.

### Required validation

- [ ] Missing record, self-parent, cycle, replacement and post-mutation snapshot failure.
- [ ] Explicit delete versus ordinary borrowed-wrapper lifetime.

### Scope exclusions

- No unrelated rewrite, automatic capability activation, package publication, or repository-protection changes.
- Keep integration mechanisms in SDK and application policy/workflows in Client.
